# Исправление запуска legacy-tg после сбоя диска

Подготовлено 20.11.2026 на основе `IT-FAMCS/legacy-tg`, ветка `main`,
коммит `542e3f9a897d494d1a19927535e92a08d1f931f3`.
Архив содержит полный исходный код с исправлением. В репозиторий изменения
не отправлены, на сервере в рамках подготовки архива ничего не менялось.

## Что изменено

- `bot.py`: имя и меню сначала читаются; запись выполняется только при отличиях.
  Инициализация SQLite перенесена перед настройкой Telegram: ошибка диска
  больше не вызывает повторное изменение имени при каждом рестарте.
  Ошибка SQLite при запуске логируется без содержимого данных.
- `runtime.py`: команды также сравниваются перед записью. Проверка отсутствия
  webhook осталась обязательной, чужой webhook автоматически не удаляется.
- Новый `telegram_setup.py`: общая логика настройки. 429, HTTP5xx и временные
  ошибки транспорта для имени/меню/команд дают безопасный warning, а не падение.
  Ошибки авторизации и неправильные запросы не скрываются.
  Повторных попыток и ожидания лимита в пути запуска нет. Пропущенная настройка
  проверится при следующем запуске; фонового повторения этот патч не добавляет.
- `tests/test_bot.py`: обновлена проверка настройки и порядка запуска.
- Новый `tests/test_startup_setup.py`: проверки неизменившихся настроек,
  частичного обновления, лимитов, недоступности Telegram, ошибок авторизации,
  webhook и заполненного диска. Проверен старт обоих worker-потоков при429
  настройки команд.

Изменены именно эти пять файлов. Если после указанного коммита в main появились
новые изменения, переносите исправление с учётом них, не заменяйте весь репозиторий
устаревшим снимком. Новый модуль обязателен; Dockerfile уже копирует все `*.py`.

## Проверка

```sh
python -m unittest discover -s tests -v
```

53 теста пройдены в Python3.13, в Docker без сети и настоящих токенов.
Независимая проверка изменений не нашла блокирующих замечаний.
Эта версия исходников ещё не проверялась в production: сейчас там работает
временная серверная обёртка с аналогичной защитой.

## Публикация и снятие временной обёртки

1. Перенесите пять файлов в репозиторий, проверьте diff и тесты, затем обычным
   процессом влейте изменения в main. Существующий Actions соберёт GHCR-образ.
2. Дождитесь успешной сборки исправленного образа и его появления на сервере.
   До этого не снимайте защиту запуска.
3. В `/home/worker/famcs/deploy/docker-compose.yml`, только у сервиса `legacy-tg`,
   удалите override:

   ```yaml
   command: ["python", "/app/deploy-startup.py"]
   ```

   и только этот bind mount:

   ```yaml
   - ./telegram-startup.py:/app/deploy-startup.py:ro
   ```

   Обязательно сохраните `bot-data:/data`, env-файлы, сети и остальные настройки.
   Dockerfile сам задаёт `CMD ["python", "bot.py"]`; дополнительный command не нужен.
   Без удаления override старый wrapper будет перекрывать новый код настройки.
4. Из каталога deploy выполните:

   ```sh
   docker compose config --quiet
   docker compose --progress plain up -d --no-deps --no-build --pull never --wait --wait-timeout 120 legacy-tg
   docker inspect legacy-tg --format '{{.State.Health.Status}} restarts={{.RestartCount}}'
   docker logs --since 5m legacy-tg
   ```

5. Убедитесь, что контейнер healthy, число рестартов не растёт, `/start` отвечает,
   кнопка «Открыть Наследие» открывает сайт. Настройки401/403 и webhook не обходить.

Файл `telegram-startup.py` можно оставить как отключённый резерв. Старые env-файлы
и базу не удалять. Перед изменением compose сохраните его актуальную копию для
отката. Патч устраняет блокировку старта косметическими API-запросами, но не заменяет
контроль свободного места на диске.
