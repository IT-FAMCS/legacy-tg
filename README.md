# Наследие ФПМИ · Telegram-бот

Бот работает в личном чате и использует backend «Наследия» для авторизации и всех прав. Поле Telegram в контактах не является способом входа.

## Возможности

- `/tasks`: свои действующие таски, описание/дедлайн/мероприятие/отделы и кнопка «Выполнено».
- `/equipment`: поиск, список, карточка предмета, «Взял предмет», история; для имеющих право — создание, изменение названия/описания, передача другому аккаунту или месту хранения, ручная дата, новые места и удаление.
- `/zones`: мероприятия и их зоны ответственности, главный и помогаторы с Telegram-контактами, нужное число людей, счётчики закрытых/незакрытых зон. Пользователи с правом редактировать мероприятие могут создавать/менять зоны и назначения и очищать всех ответственных с подтверждением.
- Уведомления о назначении/снятии ответственности за таску и накануне дедлайна. По умолчанию напоминание в 10:00 Europe/Moscow; нужны действующий аккаунт и подтверждённая привязка.
- `/link`, `/unlink`, `/cancel`, `/help`, `/start`. Ввод и устаревшие кнопки можно отменить; черновики и offset сохраняются между перезапусками.

## Привязка

Войдите на сайт → свой профиль → Telegram-бот → создайте одноразовую ссылку. Откройте её в боте, нажмите Start, затем вернитесь в профиль и подтвердите показанную Telegram-личность. Пароль в чат не передаётся. До подтверждения доступа нет. Ссылка действует 10 минут, хранится на backend только в виде хеша. Один Telegram ID связывается с одним аккаунтом; перепривязка требует отключения старой.

## Настройка

Нужен Python 3.13+, только стандартная библиотека. Значения задаются окружением, Python сам `.env` не читает.

На backend:

```text
TELEGRAM_SERVICE_KEY=<случайная секретная строка не короче 32 символов>
TELEGRAM_BOT_USERNAME=<username бота без @>
TELEGRAM_NOTIFICATION_TIMEZONE=Europe/Moscow
TELEGRAM_REMINDER_HOUR=10
```

На боте (см. `.env.example`):

```text
BOT_TOKEN=<токен BotFather>
WEBAPP_URL=https://famcs-legacy.by
BACKEND_URL=https://famcs-legacy.by
TELEGRAM_SERVICE_KEY=<тот же секрет, что на backend>
BOT_DB_PATH=/data/bot.sqlite3
NOTIFICATION_POLL_SECONDS=10
```

Публичный BACKEND_URL должен использовать HTTPS; HTTP допускается для localhost/внутренней сети Docker. BOT_TOKEN хранится только у бота, не на frontend/backend. Сгенерировать сервисный ключ можно локально через `python -c "import secrets; print(secrets.token_urlsafe(48))"`; не добавляйте результат в git/логи.

```bash
python bot.py
# или после настройки .env:
docker compose up -d --build
```

Контейнер сохраняет состояние в именованном томе `bot-data:/data`; корневая ФС остаётся read-only. Один процесс бота на токен. При существующем webhook запуск останавливается, webhook автоматически не удаляется.

## Доставка и ограничения

Очередь уведомлений находится в backend-БД, действия и назначения фиксируются вместе с историей одной транзакцией. Перед доставкой перепроверяются текущий аккаунт, привязка, ответственность и доступ к карточке. При удалении ответственности и потере доступа отправляется обезличенный текст. Перепривязка не доставляет старые уведомления новому чату.

Повторы временных ошибок используют lease/backoff; Telegram 429 ставит общую сохраняемую паузу отправки. Заблокировавший бота пользователь не вызывает бесконечную рассылку; контакт возобновляется после его обращения. Напоминания не догоняются после наступления дня дедлайна. Выполненные/архивные таски исключены. Исторические назначения при первой привязке не рассылаются.

Exactly-once доставка Telegram не гарантируется: при потере ответа после фактической отправки возможен повтор сообщения. Изменения данных защищены отдельными атомарными receipt-ключами: повтор команды не создаёт второй предмет/историю. Состояние диалогов и ответы записываются короткой транзакцией после сетевой работы.

`GET /healthz` проверяет свежесть polling и доставки. Токены, URL Bot API с токенами и содержимое переписки не логируются.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m py_compile bot.py chat.py clients.py store.py runtime.py worker.py zones_chat.py
```

Опциональная сквозная проверка с соседней рабочей копией backend и её окружением:

```text
../legacy-back/venv/Scripts/python.exe -W ignore tests/integration_backend.py --backend-root ../tg-back -v
```

Она использует временные базы и подменную отправку, не настоящий Telegram. Browser smoke описан в backend `docs/TELEGRAM.md`. [Деплой](DEPLOY.md).

Каждая команда изменения дополнительно связана с поколением привязки на backend. Если привязка поменялась между открытием кнопки и запросом, изменение отклоняется.
